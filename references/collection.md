# 采集与证据核对

需要发现工作、读取已选对象或核对覆盖缺口时读取对应章节。本文负责采集操作和证据含义；候选选择由交互规则负责，报告表达由写作规范负责。
`<skill_dir>` 是本 skill 的 `SKILL.md` 所在目录的绝对路径。

## 采集前置条件

### 作者与项目

配置不存在时先用 `python3 <skill_dir>/scripts/collect.py --whoami` 检查默认身份。
唯一全局邮箱且无相反证据时可沿用并说明；归属不明且影响内容时再问。已确认邮箱不重复询问，同名未配置邮箱不能自动算作本人。
配置路径、邮箱匹配和手工覆盖参数见 [README.md](../README.md#身份配置)。

未限定项目时使用配置；限定项目时先将名称解析为实际路径，使用 `--only-repo <仓库绝对路径>`，多个项目重复传入。
该参数同时限制 Git/fetch、PR 发现和会话留存；`--repo` 只追加仓库，不能代替严格范围。配置 `only_repos` 也可限定，CLI 优先。
会话按规范化项目路径及其子目录匹配，名称相同不能证明属于同一项目。独立 worktree 需另列路径；无法确认项目的记录计入诊断，不自动纳入。

### 日期与时区

未指定日期且上下文没有其他日期时默认今天。能按配置时区或已确认上下文解释时直接使用；只有歧义会改变内容且无法消除时才询问。
日期换算交给脚本：

| 用户说 | 参数 |
|---|---|
| 今天 | 默认 |
| 昨天 | `--date yesterday` |
| 某一天 | `--date YYYY-MM-DD` |
| 本周（周一至今天） | `--week` |
| 上周（周一至周日） | `--last-week` |
| 最近 N 天 | `--days N`，含今天 |

`--date` 是结束日，`--days N` 含结束日向前取 N 个自然日；自然周参数不能与二者同用。
日界按配置 `utc_offset_hours`（默认 +08:00）划分。提交按 committer date 归属，作者时间相差超过一天时证据另作标注；rebase/cherry-pick 的落地时间不等于新写时间。

## 发现工作

```bash
python3 <skill_dir>/scripts/collect.py --force
python3 <skill_dir>/scripts/collect.py --week --only-repo <仓库绝对路径> --force
```

默认采集 PR 关联的提交和 Claude Code、Codex、DSH 会话；具体开关见 [命令用法](../README.md#用法)。
采集器直接保存证据，不代替用户选择。拿到结果后按 [交互规则](interaction.md) 初筛，不将完整索引直接作为待选清单。

### Git 证据：PR 两层遍历

提交证据的索引是 PR，不是本地仓库：

1. **第一层**：用已登录的 `gh` 只读搜索起始时间之后更新过、且与本人有关的 PR（`involves:<登录账号> updated:>=<带时区起始时间>`）。限定项目时先加 `repo:owner/repo`，逐仓库分页搜索，每页最多 100 条；不先全局截断再过滤项目。
2. **第二层**：逐个读 PR 的提交，保留作者符合身份筛选且 committer date 落在区间内的提交。显式 `--author` 只按该正则筛选；否则按 GitHub login 或配置邮箱匹配。
3. **本地解析**：按 SHA 回本地仓库补齐改动文件和行数；本地找不到该提交时只保留平台元数据，诊断计数。

`involves:` 只匹配 author/assignee/mentions/commenter，**不含提交作者**：他人创建、含本人提交但本人从未留言的 PR 不会出现。
搜到但本期没有本人提交的 PR 仍保留，标为「本期无本人提交（可能是评审或讨论）」，由初筛判断是否算工作。
同一提交出现在多个 PR 时按 SHA 去重，保留全部关联，汇报时不视为独占归属。
搜索不限制更新时间的上界，避免漏掉本期有提交、之后又被更新的 PR；更新时间本身不能证明本人在本期参与。
遇到搜索上限（每个查询最多 1000 条）、额度用尽、分页失败或平台声明结果不完整时，保留已读取内容并标记覆盖不完整。
PR 提交列表达到平台的 250 条边界时也提示可能缺失。不能把截断后的空结果写成「本期没有工作」。

读取提交前默认逐仓库执行 `git fetch --all --no-recurse-submodules`，按远程配置更新引用，不执行 pull、merge 或 rebase；
它决定 PR 给出的 SHA 能否在本地解析。同步命令禁用终端凭据提示，默认每次超时 30 秒，可用 `--fetch-timeout <秒>` 调整。
`--no-fetch` 表示离线：同时禁用 PR 搜索，此时没有 Git 证据。`--no-prs` 单独禁用 PR 发现，效果相同。`--whoami` 和禁用 Git 时不 fetch。
缺少 gh、认证失败、限流或查询额度不足时按诊断说明覆盖缺口，不声称本期没有工作；脚本不自动登录、不写远端。查询配置见 [README.md](../README.md#github-pr-证据)。

**未在本次 PR 检索结果中找到关联的本地提交不进证据**，只在诊断里留一行计数；检索有缺口时，不能据此断言这些提交没有关联 PR。
这类工作按会话记录或用户补充材料处理，不凭计数推断内容。

### 输出与重采

- 默认最新视图：`<reports_dir>/.evidence/<YYYYMMDD>.md`，多天为 `<YYYYMMDD>-<N>d.md`。stderr 的 `[ok] N commits, M sessions -> <路径>` 指向此文件，`.evidence` 上一级即 `reports_dir`。
- 每次落盘先保存独立快照，再更新最新视图；末尾链接到本次 `evidence.md` 与 `evidence.json`。JSON 保留所有已解析、符合范围的会话事件及来源，Markdown 摘要额度不影响留存。
- 重采使用 `--force`。数量减少时核对范围变化或原始记录缺失；旧证据位于历史快照，不直接混合新旧计数，引用旧版时标明生成时间。原始会话可能被清理，不假定历史证据可重建。
- `--keep` / `evidence_keep` 仅清理最新 Markdown 视图，不清理 `.history`。`--print` 仍执行启用的采集，但不保存 JSON 或快照。
- 脱敏默认开启；仅在用户明确要求时使用 `--no-redact`。规则不完备，写稿仍须检查敏感信息。
- `--dirty` 附带当前 tracked 文件的未提交改动。配置 `dirty` 只在区间包含今天时生效，显式参数对历史区间也采集运行时状态；不代表历史状态，未入索引的新文件不可见。

## 读取已选对象

### PR Description 与本期提交

选中含 PR 的事项后，使用采集包链接的本次 `evidence.json`：

```bash
python3 <skill_dir>/scripts/pr_details.py \
  --evidence <本次快照/evidence.json> --pr owner/repo#43 \
  --out <reports_dir>/.evidence/<日期>-selected-prs.md
```

多个已选 PR 重复传 `--pr`；更新同名分析证据用 `--force` 保存新快照。脚本只允许读取原快照中已发现的指定 PR，默认脱敏。
Description 与逐条 commit message 保存在独立 JSON；脚本不采集 diff。用户要求离线时仅使用已有材料，不运行该网络查询。
选中的评审或讨论类 PR 即使没有本人提交，也可读取 Description；它只说明背景。需结合带时间的评审/评论记录或用户说明确认本人本期参与的内容，不能写成实现了整个 PR。原快照未查询或查询失败的情况继续保留为缺口，不当作没有提交。

| 证据 | 核对方式 |
|---|---|
| Description、状态、获取时间 | 当前版本用于理解整体目标，不能冒充历史快照；报告日期之后的更新只能标为后续情况。 |
| `period_commits` 及 commit message | 对应原快照中本人区间内提交；逐项检查本期贡献，不能当作整个 PR 的成果或首次加入 PR 的时间证明。 |
| 改动本身 | commit message 是作者自述。不足以说明做了什么、或需要核实标题与改动是否相符时，按 SHA 自行 review：`git -C <repo_path> show <sha>`；只读所选提交，不扩展到整个 PR。 |
| 一个 SHA 关联多个 PR | 保留关联，汇报时去重，不视为独占归属，不将他人改动算作本人贡献。 |
| `merged_at`、测试记录 | 分别核对时间和直接证据；本地提交不证明合并，读取时状态不能倒填到历史区间。 |

没有可用 PR 材料时，基于已选提交/会话保守描述，不猜 PR 编号、动机或合并状态。输出资料不等于已完成分析，归纳方法见 [写作规范](writing.md#归纳本期贡献)。

### 会话与文档

会话摘要有损，关键决策或状态按 ID 回查 JSON 的 `sessions[].events`。`source`、`line`、`at` 定位原始记录，`call_id` 关联工具调用和结果；DSH 行号按解压后的 JSONL 计算。
只读取相关区间及理解所选片段必需的上下文，不扩展到会话的其他工作。用户请求是意图，助手陈述是自述；工具结果需结合调用、退出状态、验证范围和后续事件判断。

补充文档按指定链接、路径或内容读取，不自行扩展到整个云盘或其他项目；用户明确纳入的配置外文档仍是已选来源。
保留标题、来源及可得的版本/获取时间，通过版本记录、会话或用户说明核对本人在区间内的新写、修订或评审贡献。
无法访问时请求必要内容，继续其他已选事项；仅当归属或时间缺失会改变结论时追问。

## 证据线索与覆盖缺口

| 线索 / 诊断 | 含义 |
|---|---|
| 完整索引、摘要省略 | `max_sessions` 只限制详细摘要，按日期、项目分配；索引和 JSON 可用于初筛，工具步数不代表重要性。 |
| 未启用、不可用、部分失败、无记录 | 分别描述；来源缺失或读取失败不等同于当天没有工作。Git 按仓库、会话按文件计数。 |
| `scope_excluded` / `scope_unknown` | 已知范围外或项目无法确认的会话未纳入证据；不代表解析失败。 |
| `out_of_scope`（PR） | `--only-repo` 限定下，本地没有对应仓库的 PR 未纳入。 |
| `git_fetch` / `pr_diagnostics` | 逐仓库同步结果及 PR 搜索覆盖；失败、跳过或超出查询额度时不声称已同步或完整覆盖。 |
| `search_truncated` / `search_incomplete` / `searches_skipped` / `commit_lists_capped` | 搜索截断、平台声明不完整、尚未搜索的仓库、达到提交列表边界；任一出现都按覆盖缺口处理。 |
| 主题候选、可能相关提交 | scope 聚合和文件路径交集只是线索，需结合实际任务确认关联。 |
| 本期无本人提交的 PR | `involves` 命中但第二层没筛出提交：可能是评审、讨论或他人推进，需初筛确认本人在本期的参与形式。 |
| `local_unassociated` | 本地本人提交未在本次 PR 检索结果中找到关联，未纳入证据；要写这部分工作须另有来源。 |
| `commits_without_local_copy` | PR 提交在本地找不到（未 fetch、在别的机器上提交、历史被改写），只有平台元数据，无法在本地核对改动。 |
| `另有 N 个副本` | patch-id 相同的 rebase/cherry-pick 副本按同一事项处理；标题或文件相同不足以判定重复。 |
| `↻ 同开场白 N 段` | 同一对话的分叉或续聊，内容可能不同，不能直接重复计数或丢弃。 |
| `stale_days` | 距仓库最近提交的时间，不是当前未提交改动的持续时间。 |

采集按既定目录和 mtime 预筛，不证明范围之外没有记录；DSH 依赖 `zstd`，格式漂移或损坏会产生诊断。
来源不可用时继续有据的已选工作；无法支撑任何内容时请求必要材料，不展示空选择题或编造报告。
