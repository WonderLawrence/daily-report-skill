# 采集与证据核对

**确定范围 → 采集候选 → 用户选择 → 读取详情 → 核对贡献与缺口。**

按当前阶段阅读；候选选择见 [交互规则](interaction.md)，报告表达见 [写作规范](writing.md)，字段解释见文末 [参考](#字段与诊断参考)。
`<skill_dir>` 为本 skill 的 `SKILL.md` 所在目录的绝对路径。

## 采集前置条件

### 作者与项目

配置不存在时运行 `python3 <skill_dir>/scripts/collect.py --whoami`。唯一全局邮箱且无相反证据时可沿用并说明；归属不明且影响内容时再问。已确认邮箱不重复询问，同名未配置邮箱不自动算本人。配置与覆盖参数见 [身份配置](../README.md#身份配置)。

未限定项目时沿用配置；限定时解析为绝对路径，用 `--target-project <路径>`，多项目重复传入。它覆盖 `target_projects` 配置，同时限制 Git/fetch、PR 和会话；`--repo` 只追加范围。
会话按规范化路径及子目录匹配，独立 worktree 另列。同名不能证明同一项目，路径不明的记录只计入诊断。
这里填写项目工作目录，不是会话日志目录。启用 Git 时每项必须是仓库根目录；禁用 Git 后可用非 Git 目录筛选会话，当前不能混用这两种范围。

### 日期与时区

未指定日期时沿用上下文，无日期信息才默认今天。按配置时区解释；仅在歧义会改变内容且无法消除时询问。日期由脚本换算：

| 用户说 | 参数 |
|---|---|
| 今天 | 默认 |
| 昨天 | `--date yesterday` |
| 某一天 | `--date YYYY-MM-DD` |
| 本周（周一至今天） | `--week` |
| 上周（周一至周日） | `--last-week` |
| 最近 N 天（含今天） | `--days N` |

`--date` 为结束日，`--days N` 含结束日向前取 N 个自然日；二者不能与自然周参数同用。
日界按 `utc_offset_hours`（默认 +08:00）划分。提交按 committer date 归属，与作者时间相差超过一天时另作标注；rebase/cherry-pick 时间不等于新写时间。

## 发现工作

按范围添加日期和项目参数，采集并保存回执：

```bash
python3 <skill_dir>/scripts/collect.py --overwrite --json > <采集回执.json>
```

默认采集 PR 关联提交及 Claude Code、Codex、DSH 会话，其他开关见 [命令用法](../README.md#用法)。结果须按 [交互规则](interaction.md) 初筛后交用户选择，不能将完整索引直接当作待选清单。

采集或辅助 `gh api` 查询失败时，区分连接失败、认证/权限不足与成功返回空结果。疑似沙箱网络限制时，按当前环境的审批机制申请所需权限，获准后重试同一查询；未获准或重试仍失败，就记录缺口并继续已有证据，不绕过审批或无限重试。仅凭连接错误不能认定 GitHub 服务故障，也不能解释为没有工作记录。

### Git 证据：PR 两层遍历

1. 用已登录的 `gh` 搜索起始时间后更新、与本人有关的 PR。限定项目时逐仓库分页，每页最多 100 条；不先全局截断再过滤。
2. 在每个 PR 内按作者和 committer date 筛出本期提交。显式 `--author` 只按正则筛选，否则按 GitHub login 或配置邮箱匹配。
3. 按 SHA 回本地补齐文件和行数；同一 SHA 去重并保留全部 PR 关联，不视为独占归属。

`involves:` 匹配 PR 作者、指派、提及和留言，**不按提交作者搜索**，仅贡献提交可能漏检。搜索不设更新时间上界，以免漏掉后来更新的 PR；更新时间本身不证明本人本期参与。无本期本人提交的 PR 仍保留，供初筛辨认评审或讨论工作。

每个搜索查询最多覆盖 1000 个 PR，单个 PR 提交列表的边界为 250 条。达到边界、额度用尽、分页失败或平台声明不完整时，保留可得内容并报告覆盖缺口。
**本次未找到 PR 关联的本地提交只计数，不进入证据**；不据此断言没有关联 PR，相关工作须用会话或补充材料支撑。

默认先执行 `git fetch --all --no-recurse-submodules` 以便本地解析 SHA，只更新引用，不执行 pull、merge 或 rebase。同步禁用终端凭据提示，每次默认 30 秒，可用 `--fetch-timeout` 调整。
`--no-fetch` 同时禁用 PR 搜索；`--no-prs` 只禁用 PR 发现，仍可能 fetch。两者均不产生提交证据；`--whoami` 和禁用 Git 时不 fetch。脚本不自动登录或写远端，查询配置见 [README](../README.md#github-pr-证据)。

### 输出与重采

- `--json` 将回执写到 stdout、诊断写到 stderr。直接把回执交给后续脚本，不从 Markdown 猜路径。
- 最新视图为 `<reports_dir>/.evidence/<YYYYMMDD>.md`，多天为 `<YYYYMMDD>-<N>d.md`。每次落盘先存独立快照，再更新最新视图；JSON 保留全部已解析且符合范围的事件。
- 每次运行都会重采；`--overwrite` 允许覆盖同名输出，旧证据保留为快照。数量减少时检查范围变化或源记录丢失，不混合新旧计数；引用旧版须标明生成时间，不能假定已清理的记录可重建。
- `--keep` / `evidence_keep` 只清理最新视图，不删历史快照。`--print` 仍采集，但不保存 JSON 或快照。
- 默认脱敏，仅在用户明确要求时用 `--no-redact`；写稿仍须检查敏感信息。
- `--dirty` 采集当前 tracked 文件的未提交改动，不含未入索引的新文件。配置 `dirty` 仅在区间含今天时生效，显式参数也可用于历史区间，但结果始终是运行时状态。

### 读取证据

用 `read_evidence.py` 读取已有本地证据。参数和示例见该脚本及 `pr_details.py` 的 `--help`；实际字段、类型和长度由读取脚本的默认输出提供。

- 使用本次回执定位快照；旧回执在重采后仍指向旧版，不与最新视图混用。
- 初筛先读索引，选定对象后再读正文。按实际字段读取，不用默认空值掩盖字段或结构错误。
- 需要全文时按返回的续读位置读到结束，不能把一页当作全部内容。
- 读取成功只说明本次读取有效；证据完整性和工作状态须另行核对。

## 读取已选对象

### PR Description 与本期提交

用采集回执或快照 `evidence.json` 读取已选 PR：

```bash
python3 <skill_dir>/scripts/pr_details.py --evidence <采集回执.json> \
  --pr owner/repo#43 --out <PR详情.md> --json > <PR详情回执.json>
```

只允许指定原快照内的 PR；多项重复 `--pr`，覆盖用 `--overwrite`。脚本默认脱敏，保存 Description 和完整 commit message，不采集 diff；离线时只用已有材料。
先检查 [详情完整性](#pr-完整性与提交字段)，再按 [读取约定](#读取证据) 分页读全文。退出码 0 仅表示保存成功。

| 证据 | 核对重点 |
|---|---|
| Description、状态、获取时间 | 用于理解整体目标；当前版本不能冒充历史快照，报告区间后的更新标为后续情况。 |
| 本期提交及 message | 只归纳本人区间内贡献，不代表整个 PR 的成果或提交首次加入 PR 的时间。message 是作者自述；说不清改动或需核实时，对所选 SHA 执行 `git -C <repo_path> show <sha>`，不扩展到整个 PR。 |
| 合并时间、测试记录 | 核对时间和直接证据；本地提交不证明合并，当前状态不能倒填到历史区间。 |

无本人提交的 PR 可读背景，但本期参与须由带时间的评审/评论或用户说明支撑。提交查询未完成属于缺口，不当作没有提交。PR 材料不足时基于已选提交/会话描述，不猜编号、动机或合并状态。

### 会话与文档

会话摘要有损，关键决策和状态须按 ID 回查事件，遵循 [读取约定](#读取证据)，定位字段见 [参考](#会话事件与来源定位)。只读相关区间及理解已选片段必需的上下文。用户请求是意图，助手陈述是自述；工具结果须结合调用、退出状态、验证范围和后续事件判断。
工具调用和结果只在同一 agent、同一会话内按有效 `call_id` 关联；两个空值不构成配对。ID 缺失或对应关系有歧义时，按来源行号回查原始记录，不能只凭时间相邻判定配对，未确认前不据此声称验证通过。

文档只读指定链接、路径或内容；用户明确纳入的配置外文档也有效，不扩展到整个云盘或其他项目。保留标题、来源和可得的版本/获取时间，用版本记录、会话或用户说明核对本人本期贡献。无法访问时请求必要内容并继续其他已选事项；仅在归属或时间缺失影响结论时追问。

## 字段与诊断参考

字段名和结构以读取脚本返回的元数据为准，以下仅解释证据含义。

### PR 完整性与提交字段

先看顶层 `status` 和 `summary`；终端与 Markdown 同样显示完整性。

| 字段 | 含义 |
|---|---|
| `status` 为 `partial` | PR 详情失败、已知 message 缺失、提交列表未查完或达到平台上限；已查完且无本期本人提交不算失败。 |
| `status` 为 `complete` | 仅所选详情及已知提交完整，不证明搜索覆盖全部工作、本人完成了工作或改动已验证。 |
| `summary` | 汇总详情、message 和列表缺口。 |
| `failures` | 仅记录 PR 详情接口失败，空列表不保证资料完整。 |
| `period_commits` | 原快照中本人区间内的提交。 |
| `merged_at` | PR 合并时间。 |
| `message_source` / `message_retrieved_at` | 完整 message 的来源 / 获取时间。 |
| `local_message_error` / `message_error` | 本地读取失败（回退成功仍保留）/ 最终未取得 message 的缺口。 |

message 依次取自发现阶段保留的 API 结果、本地 Git、同仓库同 SHA 的 GitHub commit object；不读取改动文件。

### 会话事件与来源定位

| 字段 | 含义 |
|---|---|
| `sessions[].events` | 原快照中的完整已解析事件，不受 Markdown 摘要额度影响。 |
| `source` / `line` / `at` | 来源 / 行号 / 时间；DSH 行号按解压后的 JSONL 计算。 |
| `call_id` | 非空白字符串或整数，`0` 也有效；`null` 表示关联 ID 缺失或不可用，不能用于配对。DSH v4 调用取 `data.callId`，结果优先取 `data.message.toolCallId`，缺失或不可用时取 `data.message.source.callId`；消息自身 `id` 不作关联 ID。 |

AGENTS.md、Codex 审批历史、DSH 上下文和时间采样等注入块不算用户请求，同一消息中的独立真实请求仍保留。Claude `api-request-blob` 是请求副本，不作事件，也不因缺少时间戳报坏记录。

### 证据线索与覆盖缺口

分别说明未启用、不可用、部分失败和无记录，**均不能推断当天没有工作**。Git 按仓库、会话按文件计数；采集仅覆盖既定目录和 mtime 预筛范围。DSH 依赖 `zstd`，格式漂移或损坏会产生诊断。

| 线索 / 诊断 | 含义 |
|---|---|
| `max_sessions` | 仅限制按日期、项目分配的详细摘要；完整索引和 JSON 仍可初筛，工具步数不代表价值。 |
| `scope_excluded` / `scope_unknown` | 范围外 / 项目不明的会话未纳入，不表示解析失败。 |
| 会话 `issues` | 每来源最多 20 条文件、行号、错误类型，错误总数不截断；行号 0 为文件级问题。无时间戳无法归入当天，坏记录数不等于当天丢失消息数。 |
| 会话 `missing_call_ids` | 缺失或不可用关联 ID 的工具事件数；可读事件仍保留，对应文件计为部分解析。`issues` 中的 `missing_call_id` 定位到原始记录，一行可含多个事件，故条目数不一定等于事件数。 |
| `out_of_scope`（PR） | 限定项目时，本地无对应仓库的 PR 未纳入。 |
| `git_fetch` | 同步结果及失败退出码、脱敏限长的 stderr；失败或跳过不算已同步。按具体错误定位，不一律归为网络问题。 |
| `pr_diagnostics` | PR 搜索覆盖；gh 缺失、认证失败、限流或额度不足均须报告缺口。 |
| `search_truncated` / `search_incomplete` / `searches_skipped` / `commit_lists_capped` | 搜索截断 / 平台声明不完整 / 未搜索仓库 / 提交列表达上限，均属覆盖缺口。 |
| `local_unassociated` | 本地本人提交未在本次搜索中关联 PR，仅计数。 |
| `commits_without_local_copy` | 本地缺少 PR 提交，只有平台元数据，无法本地核对改动。 |
| `另有 N 个副本` | patch-id 相同的 rebase/cherry-pick 副本视为同一事项；标题或文件相同不足以去重。 |
| 主题候选、可能相关提交 | scope 聚合和路径交集只是线索，需按实际任务确认。 |
| `↻ 相同有效请求 N 段（可能相关）` | 去除注入和简单应答后，首条完整请求相同；不证明分叉或续聊，不直接重复计数或丢弃。 |
| `stale_days` | 距最近提交的时间，非未提交改动的持续时间。 |

来源不可用时继续有据的已选工作；无内容可支撑时请求必要材料，不展示空选择题或编造报告。
