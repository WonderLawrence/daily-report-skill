# 候选确认与对话状态

需要初筛候选、确认事项、补充材料或在后续对话中变更范围时读取。本文只维护交互规则，采集操作见 [collection.md](collection.md)，已选内容的归纳见 [writing.md](writing.md)。

## 选择的依据

日期、作者和项目决定发现范围，不表示其中所有对象已选定。“直接回复”只决定交付方式。
明确要求基于所给材料写稿、指定具体 PR/会话片段/文档或授权自动筛选时，沿用该选择。
自动采集结果、agent 自行发现的材料和历史报告不能充当用户选择。只有用户明确要求无需询问时，才跳过相应提问。
仅润色现有文本直接处理；不重新发现对象或补问材料。

## 初筛并形成工作事项

先读采集诊断、Git/PR 同步结果和完整会话索引。未启用、不可用、读取失败、项目无法确认、未查到记录分别说明；空结果不证明没有工作。
`max_sessions` 只限制详细摘要，不决定工作价值；完整索引和 JSON 中的区间内事件均可用于初筛。

确认前只辨认工作，不提前写成果分析：

- 从提交标题、PR 编号/标题及参与线索、会话索引、文档标题和活动说明中确定具体对象与活动。
- 线索不足时只查看辨认任务所需的少量区间内文字事件、配对工具调用与结果；一旦能说明“围绕什么做了哪类工作”就停止初筛，细节留到选中后读取。
- 初始化、心跳、只有“继续/好的”、空内容或初筛后仍无法辨认用途的记录不列给用户选择。不要以“未知会话”“索引无请求摘要”占位。原始证据仍留存；解析失败须作为缺口说明。
- 没有用户请求但有分析结论或工具产出的续接会话仍需初筛，不能直接丢弃。助手陈述仅为自述；工具步数和文件数不代表成果或价值。

**默认以工作事项为选择单位。** 一个事项可以关联多个 PR、提交、会话和文档；保留每个来源的标识，允许用户单独排除来源或限定片段。
只有来源明确提到同一 PR/任务、明确的依赖关系或用户确认时才合并。文件路径交集、同仓库和关键词相同只是弱线索，无法确认时分开列出。

| 编号 | 工作事项 | 本期活动线索 | 来源 |
|---|---|---|---|
| W1 | RPC 空结果编码修复 | 本人有区间内提交，会话讨论兼容性 | PR owner/repo#43、提交 SHA、会话 ID/片段 |
| W2 | 存储恢复方案评估 | 比较快照恢复与日志回放 | 文档链接、会话 ID/片段 |

示例不是事实来源。实际清单使用稳定的 W 编号，重采后不重排旧编号；新增事项另编号。
标题说清工作，不将待核验的“性能提升/已完成”作为成果。没有有效候选时说明范围内缺口，不展示空选择题。

## 分开记录对象选择与材料补充

在当前对话中维护以下简短范围记录，不要求用户填写表格，也不将它混入正式报告：

| 字段 | 内容 |
|---|---|
| 时间和项目 | 当前日期窗口、时区、项目路径 |
| 事项与来源映射 | W 编号 → PR ID、SHA、会话 ID/片段、文档链接 |
| 对象状态 | 每项为待选、已选或排除；另外保留被排除的单个来源 |
| 文档补充状态 | 未问、待答复、已提供、无补充或按用户要求跳过；附对应用户答复 |

一次交互中展示初筛后的事项，请用户选择全部、编号或排除项。用户最初未提供足够材料时，同时补问：
“关注时间段内，是否还有当前仓库、PR 和会话范围之外的文档产出需要纳入，例如设计文档、评审记录或调研总结？可以提供链接、本地路径或内容，也可以说明没有补充。”
不因自动采到了足够写一段报告的记录而省略补问。已有答复、明确只用指定来源、用户已提供并选定完整材料或明确无需询问时，记录相应状态，不重复提问。

| 用户答复 / 当前状态 | 更新与下一步 |
|---|---|
| “只选 W1” | W1 已选，其余当前事项排除；文档状态仍待答复，可处理 W1，不解释为没有文档。 |
| “全部” | 只选中当前清单全部事项；不自动选未来新事项，也不代表没有补充文档。 |
| “没有其他文档” | 仅更新文档状态；尚未选择的事项仍等待选择。 |
| “W1 加上这份文档” | 选中 W1，补充文档视为已选来源；已有选择不重问。 |
| 没有答复 | 对象保持待选，不深入分析或写入报告；可以做独立覆盖检查。 |
| 已有已选事项，文档待答复 | 可分析并交付当前已选范围，说明覆盖；不声称“没有其他文档”，不重复催问。 |
| 全部排除且没有补充 | 不编造报告，说明本次没有选定工作；不说当天没有工作。 |

重写同一报告沿用已选/排除状态。重采新增事项默认待选，只在需要扩大范围时询问新增项，不阻塞已选工作。
用户选择片段时，仅分析该片段及理解含义/状态必需的相邻上下文，不扩写为整段会话的其他工作。用户主动排除不算采集失败。
