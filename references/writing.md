# 报告归纳与写作

为已选事项写稿、审稿或润色时读取。默认读者是技术负责人，了解领域但未必熟悉任务背景；用户指定的受众、格式和篇幅优先。

**写作重点是各工作项实际完成的内容，主次分明、表达简洁、容易理解。** 先说清做了什么，再补充理解这项工作所需的背景和细节。

**归纳本期贡献 → 组织工作主题 → 选择正文细节 → 审稿与改写。**

## 归纳本期贡献

先提炼每项工作本期完成的改动、形成的结论或产物。保留来源 ID、时间或 commit SHA 供追溯，核对细节不必全部写入正文。读取与核对方法见 [已选证据核对](collection.md#读取已选对象)。

- 只归纳已选范围内的本人本期贡献，不把整个 PR 的成果或他人的历史材料算作本人产出。跨天会话只计所选区间内有事件支持的工作。
- 调查、评审、答疑、方案取舍和文档新写或修订也可作为产出；只保留影响结论的过程，不将阅读材料或计划方案写成已实现成果。
- 动机、收益和计划须有依据。仅有提交时描述具体变化；没有测量数据时，不补写“性能提升”“稳定性增强”等结论。

## 组织工作主题

按共同目标及有证据的任务关联归并，同一工作在 PR、提交、会话和文档中只描述一次。跨仓库可以是同一主题，同仓库或关键词相同不足以合并；不先按 `feat`、`fix` 等提交前缀分栏。

优先突出用户关心的工作和材料中的主要成果。重要工作先写、适当展开，辅助修改合并简述；篇幅不按提交数或记录多少平均分配。

每项先用一句话说明对象和本期完成的内容，再交代最关键的变化、原因或方案。先说“查询旧快照时，跳过快照创建后写入的数据”，再解释索引如何支持这一变化。缺少背景依据时直接描述改动。

配套修改说明彼此关系，不让读者自行拼接提交清单。围绕主要成果组织相关子项，未实施的否决方案仅在解释关键取舍时纳入。

### 结构与篇幅

- 以工作主题、项目或工作流为主要栏目，用 `##` 标题；默认用仓库名概括范围。标题写对象和动作，背景及方案取舍融入正文，不贴文件路径清单或逐条翻译 commit message。
- 同一主题中的修复、优化、调查和待办一起组织；仅在事项独立且按性质更易读时单独分栏。长主题可分子项，短事项直接用段落或条目。
- 日报写具体完成内容，周报按主题归并，季度或年度按项目、里程碑概括。篇幅随内容和读者需要调整，不凑条数、不硬合并，也不为缩短文字省略关键条件。

### 模板与示例

```markdown
# YYYY-MM-DD 工作日报

## <项目 / 工作主题>

<先说明本期完成的主要内容，再补充必要背景、关键改动或结论。>
```

周报标题用 `<start> ~ <end> 周报`，季度用 `YYYY年Qn 季度总结`。有明确计划时可加“明日计划”；用户要求计划但材料未给出时写“暂无明确计划”。空章节省略。

[日报](../examples/2026-10-16.md)、[周报](../examples/2026-10-12~2026-10-18.md)和[改写对照](../examples/readability.md)均为虚构示例，只展示表达方式，不作为事实来源。

## 选择正文细节

- 优先保留能解释完成内容和关键变化的细节，次要实现、操作过程和数量能省则省。影响结果理解或使用的条件，如“旧数据需重写后生效”，仍须说明。
- **项目组惯用的英文专有名词保留英文，不强制翻译或生造中文名称。** 沿用材料中的名称和大小写；读者可能不熟悉时，简短解释它在这项工作中的作用，不用译名替换原名。
- 实现名、配置、版本、命令和测试数量，仅在定位变化、说明条件或支撑结论时保留。用户要求的名称、版本和部署参数须完整保留。说明术语之间的关系，避免堆砌名词，也不必解释读者熟悉的概念。
- 一句围绕一个主要意思。细节过多时先取舍，再拆句或分段，保留必要的解释和连接词。

进度、验证和待办属于补充信息，仅在影响读者理解完成范围、使用条件或后续安排时简要交代，无需逐项列出提交、合并和测试状态。补充这些信息时：

- 按证据说明范围，不把本地提交当作已合并、局部测试当作全量通过、助手自述当作已验证；未知情况不猜测。
- 进度跟随对应工作项，不将后续合并倒填到本期，也不将“尚未合并”改成暗示流程已就绪的“等待合并”。
- 已回退的尝试不算最终成果，回退范围须有依据。运行时未提交改动只作为当前工作区快照，不推断历史状态或积压时长。

## 审稿与改写

以未参与任务的读者身份通读初稿，不打开证据链接，检查能否说清每项工作完成了什么、重点在哪里。发现问题后实际改写：

- **内容**：每项是否讲清实际完成的改动、结论或产物，避免空泛概括？
- **主次**：重要工作是否突出，辅助修改是否简述，配套关系是否清楚？
- **表达**：句子是否简单连贯，英文专有名词是否沿用项目组惯例，是否去掉无助理解的细节？
- **事实**：是否仅包含已选、有据的内容，保留影响结论的条件和缺口，且不泄露敏感信息或评价同事？
